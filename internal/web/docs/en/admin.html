Users, invitations and settings

Administrators manage accounts and the server's rules. They have a vault like everyone else — and, like everyone else, cannot read other users' vaults.

Roles

RoleMay
Useruse an own vault
Administratoralso invite and manage users, read the audit log and change the settings

Inviting users

Accounts are made only by invitation. Under Users → Invite a user enter the e-mail address and the role. PassZit shows the invitation link once; send it to the person. The link works once and for the number of days in Sign-in and security (7 by default). The invited person chooses the master password and sets up two-factor sign-in. Open invitations can be withdrawn.

Managing users

  • Disable a user to stop all sign-ins at once (open sessions end). Enabling again restores everything.
  • Reset two-factor sign-in for a user who lost the phone and the recovery codes.
  • Delete the account removes the user with the personal vault for good — type the address to confirm.

Administrators cannot see or reset master passwords. A user who forgot it and has no recovery key can only start over with an empty vault: delete the account and invite again. The user list shows who has made a recovery key.

Vault policy

  • Lock the vault after inactivity (15 minutes) and clear copied passwords (30 seconds) — users may choose shorter times.
  • Minimum master password length (12) for new accounts and changed passwords.
  • Empty the trash after a number of days (30).
  • Key derivation (Argon2id): memory, passes and lanes. Stronger settings make stolen data harder to attack but every unlock slower; accounts move to new settings at their next unlock.

Sign-in and security

Session length and inactivity timeout, how many failed sign-ins block an address and for how long (doubling for repeated blocks), and how long invitations work. Blocked addresses can be released here or on the server with passzit-server --unblock-ip ADDRESS.

Network and access

The listen address, the networks allowed to connect (others are refused before TLS) and the public address used in invitation links. If you lock yourself out, run passzit-server --reset-allowlist on the server.

Audit log

Sign-ins, failed attempts, blocks, invitations, user changes, settings, master-password changes and recovery are recorded with time, user and address. Every entry contains a hash of the previous one; the page shows whether the chain is intact. The log never contains passwords or item contents.
