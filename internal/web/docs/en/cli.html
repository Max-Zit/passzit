Command line

The passzit command reads logins in scripts and on servers. Like the browser it decrypts everything on its own computer: the server sees only the device token and encrypted data. Every release has it for Linux (amd64, arm64) and Windows.

Signing in

passzit login --server https://vault.example.com --email me@example.com

It asks for the master password and the code of your authenticator app, then appears under My account → Active sessions as "PassZit CLI on computer", where you can sign it out. The device token is kept in your configuration folder (~/.config/passzit/cli.json, on Windows %APPDATA%\passzit\cli.json), readable only by you. Only HTTPS servers are accepted.

Unlocking for a session

export PASSZIT_SESSION="$(passzit unlock --raw)"     # Linux, macOS
$env:PASSZIT_SESSION = (passzit unlock --raw)        # Windows PowerShell

The session key in PASSZIT_SESSION opens a copy of your account key that unlock stored sealed; without the variable the copy is useless. passzit lock removes the copy. Without PASSZIT_SESSION every command asks for the master password.

Reading logins

passzit list github                 # items whose name, user name or address contain "github"
passzit get password "GitHub"       # only the password, for scripts
passzit get username GitHub
passzit get totp GitHub             # the current one-time code
passzit get notes "Router office"
passzit get item 3f2a9c1e           # the whole item as JSON (id or its first 8 characters)
passzit generate --length 24

A name that fits several items is refused with the list of their ids; use the id then. The command line reads your personal vault and the shared vaults you are a member of; it does not change items.

Status and signing out

passzit status
passzit logout

Changing device passwords automatically

For a login with a remote connection, choose under Change the password on the device how the device takes a new password — Linux / Unix (SSH, passwd), MikroTik RouterOS (SSH, /password) or Windows (OpenSSH, a local account) — and how often (days). Then:

passzit rotate --due --dry-run      # what is due
passzit rotate --due                # change all that are due
passzit rotate "Branch router"      # change one now

For each item the command makes a new random password, signs in to the device over SSH with the current one and changes it there, checks the new one with a fresh sign-in, and only then saves it in the vault; the old password goes into the item's password history. If saving fails, it prints the new password so it is never lost. The first SSH key of each device is remembered (known_hosts.json next to cli.json); a different key later stops the change.

Run it daily on an administrator's computer or a management server, for example with cron (0 3 * * * PASSZIT_SESSION=… passzit rotate --due) or the Windows Task Scheduler. The PassZit server never sees the passwords: everything happens where the command runs. A schedule that holds PASSZIT_SESSION can open the vault, so use a dedicated account with only the vaults of these devices, on a protected machine.
