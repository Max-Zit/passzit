How PassZit protects your passwords

PassZit is built so that a stolen server, database or backup reveals nothing: the server stores only encrypted data and never receives your master password or any key it could use.

End-to-end encryption

  1. Your browser turns the master password into a master key with Argon2id (64 MiB of memory, 3 passes by default — slow on purpose, so guessing is slow too). A random salt per account makes every result unique.
  2. From the master key the browser derives two different keys: an auth key, which is sent to the server to prove that you know the password, and a wrap key, which never leaves the browser.
  3. The wrap key opens your account key — a random 256-bit key the server stores only in encrypted form. The account key opens the key of your vault, and the vault key encrypts every item with AES-256-GCM.
  4. Everything about an item is encrypted: name, user name, password, websites, notes, fields, folder and history. The server sees only that an item exists, its size and when it changed.

The server hashes the auth key once more with argon2id before storing it. Even the auth key does not help an attacker: the wrap key cannot be computed from it.

Each account also has an X25519 key pair; it will be used to share vaults with other users (later versions) without the server being able to read the shared keys.

Forgotten master password

Because the server never knows the master password, nobody can reset it. There are two ways back into a vault:

  • The recovery key (32 letters and digits). It opens a second copy of your account key and lets you choose a new master password. Make it in My account, print it or write it down and keep it offline. Recovery also needs your second factor.
  • Without a recovery key the vault is lost. An administrator can delete the account and invite you again — with an empty vault.

Two-factor sign-in

Every account needs an authenticator app (TOTP). A stolen master password alone does not sign anyone in. Keep the ten recovery codes: each replaces the app once. An administrator can reset the second factor of a user who lost both.

In the browser

  • Unlocked keys are kept only in memory and, encrypted with a key that only the server session knows, in the session storage of this tab. Locking, signing out or closing the session makes them useless.
  • The vault locks after the inactivity time of the policy; copied passwords are cleared from the clipboard after 30 seconds (by default).
  • The pages use a strict content security policy: only PassZit's own scripts run, nothing is loaded from other servers.

Honest limits

  • The web vault's JavaScript comes from your server. Someone who fully controls the server could serve changed code and catch master passwords typed afterwards. Protect the server like any other critical system; the browser extensions bring their own code, which the server cannot change.
  • Malware on your own computer can read what you type and what the browser shows. Keep your devices updated.
  • A weak master password can be guessed from a stolen database — slowly, but it can. Use a long passphrase.

Server protection

HTTPS only, accounts only by invitation, blocking of addresses after failed sign-ins, short sessions, an allow-list of networks, a hash-chained audit log that shows any change, and cookies that cannot be read by scripts or sent by other sites.
