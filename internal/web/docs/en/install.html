Installing the server

PassZit is one program, passzit-server, with a PostgreSQL database. Install it with the one-line installer, from the Linux packages, or as a ready appliance image.

Requirements

  • Linux: Debian 12+, Ubuntu 22.04+, AlmaLinux or Rocky Linux 9+ — x86_64 or arm64; 1 CPU, 1 GB RAM, a few GB of disk.
  • PostgreSQL 14 or newer (the installer sets it up on the same server).
  • For browser extensions and phones: a name and a certificate the browsers trust — extensions refuse self-signed certificates. Put PassZit behind your reverse proxy with a certificate, or replace the files in /var/lib/passzit/tls.

One-line installer

As root on a fresh server:

curl -fsSL https://github.com/Max-Zit/passzit/releases/latest/download/install.sh | sudo sh

It installs PostgreSQL, downloads the newest release, checks its signature (only releases signed with the PassZit release key are installed), creates a database with a random password, starts the service and prints the address and the setup token. Open https://SERVER:8443, enter the token and create the first administrator with two-factor sign-in.

Options (sh -s -- OPTIONS when piped): --version X a certain release, --db URL an existing PostgreSQL database, --no-auto-updates leave the operating system's automatic security updates off, --source URL a mirror. Running the installer again updates PassZit and keeps all data.

Linux packages

Every release has .deb and .rpm packages for amd64 and arm64. They install the program, a hardened systemd service passzit-server (own user, read-only system, no extra privileges), the root helper for updates and /etc/passzit/server.env. Set PASSZIT_DB there and start the service:

sudo apt install ./passzit-server_VERSION_amd64.deb
sudo nano /etc/passzit/server.env      # PASSZIT_DB=postgres://…
sudo systemctl start passzit-server

Appliance

The appliance images (OVA for VMware, QCOW2 for Proxmox/KVM, VHDX for Hyper-V, ISO for any machine) contain Debian, PostgreSQL and PassZit, ready to start. Sign in on the VM's console as pzadmin (first password passzit, changed at the first sign-in): a menu sets the network, the server name and the time zone, shows the setup token and restores backups. Only ports 22 (SSH) and 8443 are open.

Updates

Settings → Updates and server shows the running and the newest version. Install hands the update to the root helper: it checks the signature again, backs up the database and the program, installs the package and checks that the server comes back — if not, it puts the old version and the database back by itself. Automatic installation in a chosen hour can be switched on there.

The update channel is Stable (the newest release) or Testing, which also offers release candidates before they become stable — use it on a test server. A mirror or a local folder can be set with PASSZIT_UPDATE_SOURCE in server.env; its releases must still carry the signature.

Backup and restore

Settings → Console backup writes a backup every day (and on request) to /var/lib/passzit/backups: the database with all vaults, the secret key of the server and the console certificate. A backup is always encrypted with a passphrase you set (AES-256) — keep it somewhere else. Each backup can also be copied to an SFTP folder on another server; the first test of the connection shows the server's key fingerprint to trust.

To restore, stop the service and run the restore on the new or repaired server (the appliance menu does it for you):

sudo systemctl stop passzit-server
sudo -u passzit sh -c 'set -a; . /etc/passzit/server.env; passzit-server -data-dir /var/lib/passzit -restore /path/passzit-backup-….pzb -restore-passphrase-file /path/pass.txt'
sudo systemctl start passzit-server

The restore replaces the whole database in one step — if anything fails nothing changes. A newer PassZit migrates the restored database when it starts.

Using the web vault as an app

Browsers offer to install the web vault (Chrome, Edge: the install icon in the address bar; phones: Add to home screen). It then opens in its own window. Nothing of the vault is stored for offline use: without the server you see a short "offline" page.

Building from source

git clone https://github.com/Max-Zit/passzit
cd passzit
go run ./tools/buildwasm          # Argon2id for the browser
go build -o passzit-server ./cmd/passzit-server
export PASSZIT_DB=postgres://passzit:SECRET@localhost/passzit
./passzit-server --data-dir /var/lib/passzit --listen :8443

On the first start the server creates its secret key (secret.key), a certificate and a setup token (setup-token.txt) in the data directory.

Without the console backup, back up the database and secret.key yourself. The vaults are encrypted by the users' keys, but the server's own secrets (second factors, session keys) need secret.key.

Command-line options

OptionMeaning
--data-dircertificates, secret key, backups, logs (default /var/lib/passzit)
--dbPostgreSQL URL (or PASSZIT_DB)
--listenaddress and port, overriding the saved setting
--restore FILErestore a console backup and exit (service stopped); passphrase in PASSZIT_BACKUP_PASSPHRASE or --restore-passphrase-file
--reset-allowlistallow the private networks again and exit
--unblock-iprelease a blocked address (or all) and exit
--versionprint the version and exit
--dev-embedded-dba private PostgreSQL in the data directory — for tests and demos only
--dev-no-2fasign in without the second factor — test and demo servers only, needs --dev-embedded-db; every page shows a warning
