Remote connections

Open RDP, SSH, WinSCP, WinBox, VNC and Telnet connections straight from the browser extension, with the login saved in PassZit — without typing or seeing the password.

Saving a connection

Choose Remote Desktop (RDP), SSH with a password, SSH key, WinSCP (SFTP), WinBox (MikroTik), VNC or Telnet under New item — or edit an existing login — and fill in Remote connection: the program, the address of the device (a name or an IP address) and, if it is not the usual one, the port. For an SSH key also enter the user name. The user name and password of a login are used for the connection; an SSH key is used with its passphrase.

In shared vaults the connection needs the right Use or more. It is reported in Who used this item as "connected with it".

The MaxZit Launcher

A browser may not start programs, so a small program on your computer does it: the MaxZit Launcher for Windows — the same program WatchZit uses, so one installation serves both, and either works alone.

  1. Download it under Launcher in the menu of the web vault (WatchZit offers the same file). The installer sets it up for your Windows user without administrator rights and puts it in Apps, where it can be removed again.
  2. Pair it once per browser: Pair this browser on that page (or Pair with the MaxZit Launcher in the extension menu ≡), then allow it in the launcher's window. Pair it on the WatchZit console too if you use one.
  3. The extension menu then shows "The MaxZit Launcher answers".

On Linux the release has passzit-helper for the same job: put it in ~/.local/bin and run passzit-helper install --chrome-id ID (the ID of the extension from the browser's extensions page) or passzit-helper install --firefox once.

Connecting

Logins with a connection get a terminal button in the extension (in This site and Search). Click it and confirm. The helper then opens:

  • RDP — on Windows the Remote Desktop client (mstsc) with the login stored for a few seconds in the Windows credential manager; on Linux xfreerdp, which gets the password on its input.
  • SSH with a password — PuTTY when it is installed (password in a temporary file only the helper can read, deleted right after); otherwise the system's ssh, and the password is on the clipboard for the prompt.
  • SSH with a key — the system's ssh with the key in a temporary file that is deleted after the connection starts; a passphrase is put on the clipboard.
  • WinBox (Windows) — WinBox accepts the password only on its command line, where other programs of your Windows user can read it while WinBox runs. PassZit warns you before.
  • WinSCP (Windows), VNC (TightVNC, TigerVNC, RealVNC or UltraVNC viewer) and Telnet (PuTTY, else the system's telnet) — these programs ask for the password themselves; PassZit puts it on the clipboard for their prompt.

Copied passwords are cleared from the clipboard after the time set in the policy.

Device pages

On the device page of a monitoring console such as WatchZit, the extension shows the logins saved for that device under Device …, so you can connect from there. The page names the device in a <meta name="passzit-device"> tag; PassZit only offers logins whose connection address matches it.

One click from WatchZit

Add the console under Settings → MaxZit consoles (WatchZit) in the extension (for example https://watchzit.example.com:8443; the browser asks once for access to it). Then Open with on a device of that console opens the connection with the login saved for the device: same address and the same tool (any tool for custom tools of the console), the console's user name first. This works while PassZit is unlocked; when it is locked, or no login fits, the console opens the MaxZit Launcher as before and you type the password. The console never sees the password: it only names the device, and the extension hands the login to the launcher on your computer.

The helper gets one login per click, only from the PassZit extension (the browser checks its id), and keeps nothing. The vault stays encrypted in the browser.
